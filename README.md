# 食卓帳（meal-tracker）

写真1枚から料理名・カロリー・PFCをAI解析し、Googleスプレッドシートに自動記録するシステム。

- フロントエンド: GitHub Pages（`docs/index.html`、素のHTML/CSS/JS）
- バックエンド: Google Apps Script（`gas/Code.gs`）
- 画像解析: Gemini API（`gemini-2.5-flash`、マルチモーダル）
- データベース: Google スプレッドシート

## リポジトリ構成

```
meal-tracker/
├── gas/
│   ├── Code.gs           # GASバックエンド本体
│   └── appsscript.json   # マニフェスト（Webアプリ公開設定）
├── docs/
│   └── index.html        # GitHub Pagesで公開するフロントエンド
└── README.md
```

`docs/` を公開ルートにするのは、GitHub Pagesの設定で「Deploy from a branch」→「/docs」を選ぶだけで
リポジトリ直下を汚さずに公開できるためです。

## セットアップ手順

### ステップ1: スプレッドシートを準備する

新規スプレッドシートを作成し、URLからスプレッドシートID（`/d/` と `/edit` の間の文字列）を控えます。
シートとヘッダー行はGASが初回実行時に自動生成するので、手動でシートを作る必要はありません。

推奨カラム構成（自動生成されます）:

| 列 | 項目 | 内容 |
|---|---|---|
| A | 名前 | ニックネーム（複数人利用時の区別用） |
| B | 日付 | `yyyy-MM-dd` |
| C | 時刻 | `HH:mm:ss` |
| D | 料理名 | AIが推定した料理名 |
| E | カロリー(kcal) | 整数 |
| F | たんぱく質(g) | 小数1桁 |
| G | 脂質(g) | 小数1桁 |
| H | 炭水化物(g) | 小数1桁 |
| I | 画像URL | Driveに保存した場合のみ |
| J | 備考 | AIによる推定根拠・補足 |

> ⚠ 以前のバージョン（名前列なし）で既にテスト記録がある場合、列がずれます。
> 動作確認用の行なら削除してから使い始めるのがおすすめです。

## 複数人での利用について

ニックネームだけで区別する簡易方式です（パスワードなし）。初回アクセス時に入力したニックネームは
サーバー側（「利用者一覧」シート）で重複チェックされ、既に使われている名前は登録できません。
登録が済むとブラウザの `localStorage` に保存され、以降の記録・本日の合計・履歴はすべてそのニックネームで
スプレッドシートをフィルタして表示します。ヘッダーの「別の人に切替」から、同じ端末で別の人が
新しいニックネームを登録することもできます。

> ⚠ 制限事項: ニックネームの「所有権」は端末の `localStorage` でのみ管理しています。
> そのため、一度登録した自分の名前でも、ブラウザのデータを消したり別の端末からアクセスしたりすると
> 「既に使われています」と表示されて同じ名前を再登録できません（他人による重複登録は防げますが、
> 本人による複数端末からの利用には対応していません）。複数端末で同じ人が使いたい場合は、
> 今のところ端末ごとに少し違うニックネーム（例: `けんけん-phone`）を使うのが簡単な回避策です。

## 写真の入力方法

- 「撮」ボタン: その場でカメラを起動して撮影（`capture="environment"`）
- 「アルバムから選ぶ」: 端末に保存済みの写真（過去に撮った食事の写真など）を選択

どちらもクライアント側で最大1024pxにリサイズしてから送信するため、通信量とGemini APIのトークン消費を抑えています。

## からだの記録・基礎代謝（BMR）機能

「からだの設定」から性別・年齢・身長・活動レベルを登録し、体重を記録すると、以下を自動計算して表示します。

- **基礎代謝（BMR）** = 基礎代謝基準値（年齢・性別で決まる kcal/kg体重/日） × 体重(kg)
- **消費エネルギー目安（TDEE）** = 基礎代謝 × 身体活動レベル(PAL)
- **本日の収支** = 本日の摂取カロリー合計 − 消費エネルギー目安
- **週間の体重変化目安** = 収支 × 7 ÷ 7,200（体脂肪1kgを約7,200kcalとして換算）

基礎代謝基準値・身体活動レベルの数値は、厚生労働省「日本人の食事摂取基準（2020年版）」の公表値を
`Code.gs` にハードコードしています（出典: 健康日本21アクション支援システム 健康づくりサポートネット）。
あくまで統計的な目安であり、個人差があります。ダイエットや医療目的での厳密な栄養管理が必要な場合は、
医師・管理栄養士にご相談いただくよう、アプリ内にも注記を表示しています。

追加されるスプレッドシート:

| シート名 | 列 | 内容 |
|---|---|---|
| 利用者一覧 | 名前, 登録日時 | 登録済みニックネームの重複チェック用 |
| プロフィール | 名前, 性別, 年齢, 身長(cm), 活動レベル, 更新日時 | ユーザーごとに1行（上書き更新） |
| 体重記録 | 名前, 日付, 体重(kg), 登録時刻 | 1日1件（同日に再記録すると上書き） |
| チャレンジ | 名前, 開始日, メッセージ25, メッセージ50, メッセージ75, メッセージ100, 更新日時 | ユーザーごとに1行（100日チャレンジの設定） |
| ひとこと日記 | 名前, 日付, ひとこと | 1日1件（同日に再記録すると上書き） |

いずれも初回アクセス時にGASが自動でシートとヘッダーを作成します。

## 100日チャレンジ機能

[100日チャレンジ進捗ボード](https://kenken6291.github.io/100day-quest/)の仕組み（ドットキャラ・節目メッセージ・今日のひとこと）を、
食卓帳の記録データと連動させる形で組み込んでいます。

- **進捗**：開始日から100日間の経過日数（Day X/100）を表示。体重の数値目標は設定しません（プレッシャーになりやすいため）。
- **育つキャラクター**：進捗0/25/50/75/100%の5段階で、鉢植えの芽が育って花が咲くドット風キャラクターに成長します（`renderMascot()` でSVGを都度生成、画像ファイルは使用していません）。
- **継続の可視化**：食事・体重・ひとことのいずれかを記録した日をもとに「連続記録日数」「チャレンジ期間中の記録日数」を算出し、体重の増減そのものより「続けていること」を評価する設計にしています。
- **節目メッセージ**：25/50/75/100%到達時に、あらかじめ登録した自分へのメッセージ（未入力ならおまかせの応援文）をポップアップ表示します。到達判定はブラウザの `localStorage` で「どこまで見たか」を記録しているため、同じ節目のメッセージが毎回表示されることはありません。
- **今日のひとこと**：一言日記として毎日保存できます（60文字まで）。

体重変化・BMR/TDEEの数値はあくまで目安であることをアプリ内に明記しており、ゲーミフィケーション要素も
数値そのものへの評価ではなく「継続」を軸にしている点にご留意ください。

### ステップ2: Gemini APIキーを取得する

[Google AI Studio](https://aistudio.google.com/apikey) でAPIキーを発行します（無料枠あり）。

### ステップ3: GASプロジェクトを作成し、claspでこのリポジトリと同期する

```bash
npm install -g @google/clasp
clasp login
```

新規にGASプロジェクトを作る場合:

```bash
cd meal-tracker/gas
clasp create --type webapp --title "食卓帳バックエンド"
```

これで `gas/` フォルダに `.clasp.json`（scriptIdが書かれたファイル）が生成されます。
既存のGASプロジェクトと紐付けたい場合は `clasp clone <scriptId> --rootDir ./gas` を使います。

`.clasp.json` はscriptIdのみを含み機密情報ではありませんが、個人のプロジェクトIDが分かるため
リポジトリには含めず `.gitignore` しておくことを推奨します（下記参照）。認証情報（`~/.clasprc.json`）は
ホームディレクトリに保存されるためリポジトリには一切含まれません。

コードを反映:

```bash
clasp push
```

### ステップ4: スクリプトプロパティを設定する

GASエディタ（`clasp open` で開けます）から
「プロジェクトの設定」→「スクリプト プロパティ」で以下を追加します。

| プロパティ名 | 値 |
|---|---|
| `GEMINI_API_KEY` | ステップ2で取得したAPIキー |
| `SHEET_ID` | ステップ1で控えたスプレッドシートID |
| `DRIVE_FOLDER_ID` | （任意）食事写真を保存するDriveフォルダID |

`GEMINI_API_KEY` を設定後、GASエディタで `testGeminiConnection` を実行すると
プロパティが正しく読み込めているか確認できます。

### ステップ5: Webアプリとしてデプロイする

初回デプロイ（GUIの場合）:
「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選択し、
- 実行するユーザー: **自分**
- アクセスできるユーザー: **全員**

として公開すると `.../exec` で終わるURLが発行されます。これが `GAS_EXEC_URL` です。

claspの場合:

```bash
clasp deploy --description "v1"
```

**コードを更新したとき**は、`clasp push` でコードを反映したあと、
既存のデプロイに対して新しいバージョンを発行することで `/exec` のURLを変えずに更新できます。

```bash
clasp deployments        # デプロイID一覧を確認
clasp deploy -i <デプロイID> -d "更新内容の説明"
```

（GASエディタの「デプロイを管理」→ 編集アイコン→「新バージョン」を選ぶ操作と同じことをCLIで行っています）

### ステップ6: フロントエンドにURLを設定する

`docs/index.html` の以下の行を、ステップ5で発行された `/exec` URLに書き換えます。

```js
const GAS_EXEC_URL = 'https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxxxxxx/exec';
```

### ステップ7: GitHub Pagesを公開する

1. このリポジトリをGitHubにpush
2. リポジトリの Settings → Pages → Source で「Deploy from a branch」→ ブランチ `main` / フォルダ `/docs` を選択
3. 発行されたURL（`https://<ユーザー名>.github.io/meal-tracker/`）にスマホでアクセスして動作確認

## GitHub Actionsで自動push（任意・上級者向け）

コード変更を `git push` するたびに自動で `clasp push` したい場合は、`~/.clasprc.json` の内容を
GitHub Secretsに登録してActionsから利用する方法もありますが、認証トークンをリポジトリのSecretsに置くことになるため、
個人開発の範囲では手元で `clasp push` → `clasp deploy -i` を手動実行する運用で十分です。
自動化する場合も、`/exec` のURLを固定したまま更新する `clasp deploy -i <デプロイID>` を
ワークフローの最終ステップに必ず含めてください。

## エラーハンドリングについて

- **画像から料理を認識できない場合**: Gemini側が `recognized: false` を返すよう指示しており、
  GAS側でエラーとして扱い、フロントエンドに「認識できませんでした」と表示して再撮影を促します。
- **Gemini APIエラー・タイムアウト**: HTTPステータスとレスポンス本文をそのままエラーメッセージに含めて返すため、
  Google AI Studio側のクォータ超過なども判別できます。
- **AIの応答がJSONとして壊れている場合**: 正規表現で `{...}` 部分を抽出して救済パースを試みます。
- **Drive保存の失敗**: 記録自体は継続し、画像URLのみ空欄になります（スプレッドシートへの記録を優先）。
