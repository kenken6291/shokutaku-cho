# 食卓帳（shokutaku-cho）

写真1枚から料理名・カロリー・PFCをAI解析し、Googleスプレッドシートに自動記録するシステム。
メール＋パスワードによるアカウント管理、からだの記録（基礎代謝・消費エネルギー目安）、
100日チャレンジ、食事・体重の履歴閲覧／修正／削除に対応。

- フロントエンド: GitHub Pages（`docs/index.html`、素のHTML/CSS/JS）
- バックエンド: Google Apps Script（`gas/Code.gs`）
- 画像解析: Gemini API（`gemini-3.5-flash`、マルチモーダル）
- データベース: Google スプレッドシート
- メール送信: `MailApp`（GASの標準機能・APIキー不要。自分のGoogleアカウントの送信枠を使用）

## リポジトリ構成

```
meal-tracker/
```

## ⚠ 重要：以前のバージョンからの移行について

このバージョンから、ユーザーを識別するキーが「ニックネーム」から「メールアドレス」に変わりました。
以前のニックネームのみの版でテスト記録を入れていた場合、新しいアカウント（メールアドレス）とは
紐付きません。本番運用前に、各シートのテスト行は一度削除しておくことをおすすめします。

## セットアップ手順

### ステップ1: スプレッドシートを準備する

新規スプレッドシートを作成し、URLからスプレッドシートID（`/d/` と `/edit` の間の文字列）を控えます。
シートとヘッダー行はGASが初回実行時に自動生成するので、手動でシートを作る必要はありません。

自動生成されるシート:

| シート名 | 列 | 内容 |
|---|---|---|
| ユーザー | メールアドレス, パスワードハッシュ, ソルト, ニックネーム, 仮パスワード, セッショントークン, 規約同意日時, 登録日時, 更新日時 | アカウント情報。パスワードは平文保存しません |
| 摂取カロリー記録 | ID, メールアドレス, 日付, 時刻, 料理名, カロリー(kcal), たんぱく質(g), 脂質(g), 炭水化物(g), 画像URL, 備考 | 食事記録。IDで個別に編集・削除できます |
| 体重記録 | ID, メールアドレス, 日付, 体重(kg), 登録時刻 | 1日1件（同日に再記録すると上書き） |
| プロフィール | メールアドレス, 性別, 年齢, 身長(cm), 活動レベル, 更新日時 | ユーザーごとに1行（上書き更新） |
| チャレンジ | メールアドレス, 開始日, メッセージ25, メッセージ50, メッセージ75, メッセージ100, 更新日時 | 100日チャレンジの設定 |
| ひとこと日記 | メールアドレス, 日付, ひとこと | 1日1件（同日に再記録すると上書き） |

### ステップ2: Gemini APIキーを取得する

[Google AI Studio](https://aistudio.google.com/apikey) でAPIキーを発行します（無料枠あり）。

### ステップ3: パスワードのペッパー（秘密文字列）を決める

パスワードをハッシュ化する際に使う秘密の文字列を、自分で適当に決めます（長くてランダムな文字列であれば何でもOKです。他人に教えないでください）。

### ステップ4: GASプロジェクトを作成し、claspでこのリポジトリと同期する

```bash
npm install -g @google/clasp
clasp login
```

新規にGASプロジェクトを作る場合:

```bash
cd meal-tracker/gas
clasp create --type webapp --title "食卓帳バックエンド"
```

既存のGASプロジェクトと紐付けたい場合は `clasp clone <scriptId> --rootDir ./gas` を使います。
コードを反映:

```bash
clasp push
```

### ステップ5: スクリプトプロパティを設定する

GASエディタ（`clasp open` で開けます）から
「プロジェクトの設定」→「スクリプト プロパティ」で以下を追加します。

| プロパティ名 | 値 |
|---|---|
| `GEMINI_API_KEY` | ステップ2で取得したAPIキー |
| `SHEET_ID` | ステップ1で控えたスプレッドシートID |
| `PASSWORD_PEPPER` | ステップ3で決めた秘密文字列 |
| `DRIVE_FOLDER_ID` | （任意）食事写真を保存するDriveフォルダID |

`GEMINI_API_KEY` を設定後、GASエディタで `testGeminiConnection` を実行すると
プロパティが正しく読み込めているか確認できます。

### ステップ6: Webアプリとしてデプロイする

初回デプロイ（GUIの場合）:
「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選択し、
- 実行するユーザー: **自分**
- アクセスできるユーザー: **全員**

として公開すると `.../exec` で終わるURLが発行されます。これが `GAS_EXEC_URL` です。

claspの場合:

```bash
clasp deploy --description "v1"
```

**コードを更新したとき**は、`clasp push` でコードを反映したあと、
既存のデプロイに対して新しいバージョンを発行することで `/exec` のURLを変えずに更新できます。

```bash
clasp deployments        # デプロイID一覧を確認
clasp deploy -i <デプロイID> -d "更新内容の説明"
```

### ステップ7: フロントエンドにURLを設定する

`docs/index.html` の以下の行を、ステップ6で発行された `/exec` URLに書き換えます。

```js
const GAS_EXEC_URL = 'https://script.google.com/macros/s/xxxxxxxxxxxxxxxxxxxxxxxx/exec';
```

### ステップ8: GitHub Pagesを公開する

1. このリポジトリをGitHubにpush
2. リポジトリの Settings → Pages → Source で「Deploy from a branch」→ ブランチ `main` / フォルダ `/docs` を選択
3. 発行されたURL（`https://<ユーザー名>.github.io/shokutaku-cho/`）にスマホでアクセスして動作確認

## アカウント機能について

### 登録の流れ

1. メールアドレス・ニックネームを入力し、注意事項・免責事項に同意して登録
2. サーバーが仮パスワードを生成し、`MailApp.sendEmail()` で本人にメール送信（GAS標準機能、APIキー不要。ただし1日あたりの送信数に上限があります）
3. 仮パスワードでログイン → 初回ログイン時は新しいパスワードの設定が必須
4. 以降は設定したパスワードでログイン

### セッションについて

ログインするとサーバー側でランダムなセッショントークンを発行し、ブラウザの `localStorage` に保存します。
**同じアカウントで別の端末からログインすると、古い端末のトークンは無効になります**（1アカウント1セッション）。
これは仕様であり不具合ではありません。

### パスワードの保存方法

平文では保存せず、`SHA-256（パスワード + ユーザーごとのソルト + PASSWORD_PEPPER）` のハッシュ値のみを
スプレッドシートに保存しています。銀行水準のセキュリティではありませんが、個人開発の家族・友人向けサービスとしては
妥当な強度です。

### アカウント設定でできること

- ニックネームの変更（表示名。他の人と重複はできません）
- パスワードの変更（現在のパスワードの入力が必要）
- アカウントの削除（ログイン情報のみ削除されます。過去の食事・体重等の記録データはスプレッドシート上に
  残ります。同じメールアドレスで再登録すると、それまでの記録が引き続き表示されます）

## 履歴の閲覧・修正・削除

「本日の記録」の下にある「過去の記録をすべて見る」から、食事履歴・体重履歴を一覧表示できます
（それぞれ直近200件まで）。各項目の「編集」でAIの推定値を手動で修正、「削除」で記録を取り消せます。

## 写真の入力方法

- 「撮」ボタン: その場でカメラを起動して撮影（`capture="environment"`）
- 「アルバムから選ぶ」: 端末に保存済みの写真（過去に撮った食事の写真など）を選択

どちらもクライアント側で最大1024pxにリサイズしてから送信するため、通信量とGemini APIのトークン消費を抑えています。

## からだの記録・基礎代謝（BMR）機能

「からだの設定」から性別・年齢・身長・活動レベルを登録し、体重を記録すると、以下を自動計算して表示します。

- **基礎代謝（BMR）** = 基礎代謝基準値（年齢・性別で決まる kcal/kg体重/日） × 体重(kg)
- **消費エネルギー目安（TDEE）** = 基礎代謝 × 身体活動レベル(PAL)
- **本日の収支** = 本日の摂取カロリー合計 − 消費エネルギー目安
- **週間の体重変化目安** = 収支 × 7 ÷ 7,200（体脂肪1kgを約7,200kcalとして換算）

基礎代謝基準値・身体活動レベルの数値は、厚生労働省「日本人の食事摂取基準（2020年版）」の公表値を
`Code.gs` にハードコードしています。あくまで統計的な目安であり、個人差があります。ダイエットや
医療目的での厳密な栄養管理が必要な場合は、医師・管理栄養士にご相談いただくよう、アプリ内にも注記を表示しています。

## 100日チャレンジ機能

[100日チャレンジ進捗ボード](https://kenken6291.github.io/100day-quest/)の仕組み（ドットキャラ・節目メッセージ・今日のひとこと）を、
食卓帳の記録データと連動させる形で組み込んでいます。

- **進捗**：開始日から100日間の経過日数（Day X/100）を表示。体重の数値目標は設定しません（プレッシャーになりやすいため）。
- **育つキャラクター**：進捗0/25/50/75/100%の5段階で、鉢植えの芽が育って花が咲くドット風キャラクターに成長します（SVGをその場で生成、画像ファイルは使用していません）。
- **継続の可視化**：食事・体重・ひとことのいずれかを記録した日をもとに「連続記録日数」「チャレンジ期間中の記録日数」を算出し、体重の増減そのものより「続けていること」を評価する設計にしています。
- **節目メッセージ**：25/50/75/100%到達時に、あらかじめ登録した自分へのメッセージ（未入力ならおまかせの応援文）をポップアップ表示します。

## エラーハンドリングについて

- **画像から料理を認識できない場合**: Gemini側が `recognized: false` を返すよう指示しており、GAS側でエラーとして扱い、フロントエンドに再撮影を促します。
- **Gemini APIエラー・タイムアウト**: HTTPステータスとレスポンス本文をそのままエラーメッセージに含めて返すため、クォータ超過なども判別できます。
- **サーバー応答の解析失敗**: ブラウザ拡張機能などの影響で応答に余分な文字が混ざった場合でも、先頭のJSON部分だけを抽出して解析を試みます。失敗時はブラウザのコンソールに生の応答を出力するので、原因調査に使えます。
- **ログイン・登録関連のエラー**: メールアドレス／パスワードのどちらが間違っているかは区別せず、常に同じエラーメッセージを返します（総当たり攻撃対策）。
